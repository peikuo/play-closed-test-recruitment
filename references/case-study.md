# Android 天气应用招募阶段复盘（匿名案例）

以下是历史阶段快照，后续变化不在统计范围。项目及应用名称已泛化；未包含账号邮箱、私人聊天原文、设备标识、个人路径或Console私有URL。

## 已达到的结果与边界

Console刷新后“至少12人已参加闭测”显示完成，但没有给出精确人数；连续14天要求与生产权限审核未完成。自己的Google群有12人含开发者本人，不能据此解释Console每名测试者。

“我的群”15个群的正确拆分：11个其他应用测试群、自己的群、3个无关旧群。不能把15当作15位回测者。旧群没有未经用户要求退出。

我们实际做了：查Google Groups和Reddit的新招募，阅读条件、按作者去重、公开一对一邀请；检查评论与私聊回应；识别新增群成员并对应应用；加入对方普通测试群和核对Play入口；在用户连接的Android手机上安装和启动可用免费应用；保存真实截图、做基本功能尝试、发送真实状态与反馈；跟踪完整链接、地区、设备和上传问题；保存短状态文件并设置定时检查。没有完成14天参与验证，也没有生产发布获批结果。

## 分工

| 事项 | AI承担 | 人承担 / 平台决定 |
|---|---|---|
| 招募 | 筛帖子、去重、草拟及获授权发送 | 用户确定目标、预算、渠道与互测意愿 |
| 资格 | 核对群/opt-in/商店、记录错误 | 用户提供登录环境；平台决定地区/设备资格 |
| 手机测试 | 授权后控制已连接设备、安装启动、截图、有限核心流程 | 用户连接解锁手机、处理验证/敏感权限；复杂体验与长期自然使用需要人参与 |
| 反馈 | 记录实际步骤、整理问题、发送真实证据 | 用户补充体验判断；开发者修复、复测 |
| 监控 | 短基线、查新回应、保持事实级别 | 用户决定频率和成本；测试者决定实际参与 |
| 审核 | 汇总参与、反馈、改进证据，辅助申请材料 | 用户确认提交内容；Google决定资格与审核 |

AI能降低查找、协调与记录成本，不能制造真实测试者、代替所有长期使用，也不能保证通过。

## 有用的实践与纠错

1. 广泛联系产生的回复较少，因此持续寻找新开发者，同时为已安装对方应用提供具体证据。不能计算准确转化率：联系记录不全、时间窗口不一致，作者跨渠道可能重复。
2. 一位作者发多个应用或在多个帖子回复，只联系一次、选一个应用。用户曾明确要求某位先提供真实回测证据才回测；这是个别限制，不变成普遍以身份或国籍筛人。
3. 公开评论的作者回复曾误匹配到另一个用户。改为核对我方评论身份与嵌套分支；“给别人已安装”不能加进我方进度。
4. 群成员曾只有邮箱式显示名。通过公开作者搜索和原帖对应应用，不在状态文件存邮箱。无法对应时请求显示名。
5. 用户指出私聊已回应，才补核实并收到天气应用初次使用截图。此后区分公开评论检查与私聊检查，不笼统说“都没回复”。
6. 一款数独应用在重新连接手机后确认已安装、打开，截图通过Reddit私聊发送并核实成功。还发现以前已发的反馈链接，避免重复宣称未反馈。
7. 一款猜色游戏免费安装并打开，能进入棋盘/选色；界面波兰语，询问英文支持及测试入口。Google Groups附件上传失败，改为先发真实文字反馈并问截图接收方式，标记图片未发，而非宣布任务全部完成。
8. Play人数曾先显示10，刷新后人数门槛显示完成。保留旧显示与新证据；最终只说至少达到12，不从群人数或旧缓存猜精确值。
9. 无变化的频繁检查消耗成本，按用户要求从40分钟调整到1小时、再2小时。频率是项目选择，不是技能固定要求。访问超时记录未确认；不是没有新人。
